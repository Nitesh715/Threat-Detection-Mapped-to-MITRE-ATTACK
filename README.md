# Mini-SOC Workbench

An offline-first advanced SOC capstone project. It turns normalized endpoint and network events into rule-based alerts, correlates alerts into cases, and provides a local analyst dashboard for triage and case notes.

## Features

- Local web dashboard with summary metrics, severity distribution, incident queue, alert list, and event timeline.
- Event Explorer for searching every loaded event, including telemetry that did not trigger a rule.
- Three configurable detection types: single-event, threshold, and event-sequence rules.
- ATT&CK Enterprise technique and tactic mapping for 14 detection rules, with a searchable coverage view, telemetry prerequisites, current alert counts, and official MITRE links.
- Distinct-value thresholds for patterns such as password spraying and multi-destination network probing.
- Import adapters for normalized JSONL and Wazuh alert JSONL.
- Case correlation by shared host or source IP within a time window.
- Explainable case risk score, ATT&CK technique references, evidence event IDs, and analyst guidance.
- Local case triage: status, assignee, and timestamped notes are saved to a JSON state file.
- CLI exports alerts and cases as JSON and a readable Markdown summary.
- Synthetic training telemetry; no external services, packages, or response commands are required.

## Quick start

Requires Python 3.11 or newer. From the project directory, start the dashboard:

```powershell
python -m soc_lab.dashboard
```

Open [http://127.0.0.1:8765](http://127.0.0.1:8765). The server listens on the local computer only. Stop it with `Ctrl+C`.

Run a batch analysis and write reports:

```powershell
python -m soc_lab.cli soc_lab/assets/sample_events.jsonl --out reports/demo
```

The reports directory contains `alerts.json`, `cases.json`, `attack_coverage.json`, and `summary.md`. To use a different dataset or rule file, pass `--events` and `--rules` to the dashboard or `events`, `--rules`, and `--out` to the CLI.

Import Wazuh alerts in JSONL format with:

```powershell
python -m soc_lab.cli soc_lab/assets/wazuh_sample_alerts.jsonl --format wazuh --out reports/wazuh-demo
python -m soc_lab.dashboard --events path/to/alerts.jsonl --format wazuh
```

The adapter maps common authentication event groups and descriptions, and keeps other Wazuh alerts visible as `wazuh_alert` events in the Event Explorer. See [the Wazuh adapter guide](docs/wazuh-adapter.md) for field mapping and limitations.

Optional editable install adds the `soc-dashboard` and `soc-lab` commands:

```powershell
python -m pip install -e .
soc-dashboard
soc-lab soc_lab/assets/sample_events.jsonl --out reports/demo
```

The runtime uses only Python’s standard library. `pyproject.toml` is used for optional packaging and command entry points.

## Dashboard workflow

1. Start the dashboard; the bundled synthetic event set is analyzed at startup.
2. Open a case from the overview or incident queue.
3. Review the detection evidence and linked event timeline.
4. Set the case status and assignee, add an analyst note, then save.
5. Triage data persists locally in `data/case_state.json` and is included in the project `.gitignore`.
6. Open **ATT&CK coverage** to review the mapped techniques, tactics, data requirements, and alerts generated by the current dataset.

## Detection rules

Rules are in `soc_lab/assets/detections.json`. Each mapped rule lists ATT&CK technique ID, name, tactic(s), and required telemetry:

- `single` matches one event.
- `threshold` counts grouped matching events within a time window.
- `sequence` detects a start event followed by an end event for the same grouped entities.
- Threshold rules can count distinct field values with `distinct_by`, such as unique users or destination IP addresses.

Criteria use exact values for top-level event fields (`event_type`, `host`, `user`, `source_ip`) or dotted `details` fields such as `details.group`. Threshold and sequence rules define `group_by` fields, a time window, severity, ATT&CK mapping, data prerequisites, and suggested analyst steps. See [the detection catalog](docs/detection-catalog.md) before changing the bundled rules.

## Normalized event format

Input data is JSON Lines: one JSON object per line. `timestamp` must include a timezone. `timestamp`, `event_type`, and `host` are required; the other fields are optional.

```json
{"event_id":"EVT-0001","timestamp":"2026-11-03T14:00:00Z","event_type":"auth_failure","host":"win-lab-01","user":"analyst-demo","source_ip":"203.0.113.44","details":{"source":"synthetic training data"}}
```

The sample uses documentation-only IP ranges and synthetic events. See [the operator guide](docs/operator-guide.md) for preparing your own authorized telemetry.

## Scope and safety

This is a complete local capstone prototype, not a production SIEM. It analyzes normalized JSONL or imported Wazuh alert JSONL; it does not collect live endpoint/network data, connect to Wazuh, enrich from external threat feeds, or execute response actions. The dashboard binds to `127.0.0.1`. Use only synthetic data or telemetry from systems you own or are authorized to monitor. A production extension should add authenticated access, durable storage, access controls, audit logging, and human-approved reversible response playbooks.
